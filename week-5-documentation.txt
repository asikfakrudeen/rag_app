Week 5: Error Tracing & Telemetry (Manual Error Analysis)

Concept
Implementing a systematic tracking module to record the internal state of the application during execution, allowing developers to perform rigorous, professional-grade manual failure analysis on real-world usage.

Flow
RAG System Executes Query ➔ tracer.py Logs (Query, Retrieved Chunks, LLM Output) ➔ Data Saved to traces.jsonl ➔ Developer Reviews Sample ➔ Errors Categorized & Ranked

Explanation
In the earlier stages of development, if the RAG system returned a poor answer, diagnosing the problem involved guesswork. Was it a bad prompt? Did the semantic search fail? Did the BM25 keyword search fail? Did the reranker drop the correct chunk? "It fails sometimes" is not an actionable engineering metric.

Week 5 introduces professional-grade error tracing and telemetry to solve this. A new module, `tracer.py`, is built directly into the core RAG pipeline. Every single time a user asks a question, this tracer silently records the entire internal state of the system into a secure telemetry vault (saved as a highly efficient `traces.jsonl` file). It logs:
- The exact user query.
- The raw chunks retrieved by the hybrid search.
- The final sorted chunks output by the Cross-Encoder reranker.
- The exact prompt sent to the LLM.
- The final synthesized answer generated by the LLM.

By establishing this vault of "real-world usage data," developers can stop guessing. They can pull a random sample of actual user queries, read the exact inputs and outputs, and perform rigorous manual failure analysis. They can write honest notes about why a specific answer failed, group these failures into recurring categories (e.g., "Reranker dropping dense clauses", "LLM ignoring specific dates"), and rank them by severity. This allows the team to prioritize exactly what needs to be fixed in the pipeline based on objective data rather than ad-hoc debugging.

Advantage
Moves development away from cherry-picking good examples or ad-hoc debugging. It provides a ranked, objective list of the most critical problems based on actual application usage, making continuous improvement highly targeted and data-driven.
